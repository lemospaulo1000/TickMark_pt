4) O erro principal que impedia o add-in de aparecer no Excel

No computador alvo, o add-in não aparecia em lista nenhuma porque o MSI:

não criava as chaves do Excel em …\Excel\Addins

e não copiava o .vsto (e manifesto) para o destino que o Excel precisava

A correção foi feita em 2 frentes:

(A) Criar o registro do Add-in no Setup Project (Registry Editor)

Onde abrir o editor de registro do instalador:

Botão direito no projeto AuditorAddInRibbon_Installer

Exibir/View → Registry (Editor de Registro)

Criar a chave:

HKEY_CURRENT_USER\Software\Microsoft\Office\Excel\Addins\AuditorAddInRibbon

Criar valores dentro dela (mínimo necessário):

FriendlyName (String): AuditorAddInRibbon

Description (String): texto livre (ex.: TickMark - Auditoria)

LoadBehavior (DWORD): 3

Manifest (String): "[TARGETDIR]AuditorAddInRibbon.vsto|vstolocal"

✅ Isso fez o Excel passar a listar o suplemento.

(B) Garantir que o .vsto e o .dll.manifest são instalados (File System)

Onde abrir o File System do instalador:

Botão direito no projeto AuditorAddInRibbon_Installer

Exibir/View → File System

Em Application Folder, você já tinha “Saída Primária (Primary Output)”, mas isso não garantia o .vsto.

Então você adicionou manualmente:

AuditorAddInRibbon.vsto

AuditorAddInRibbon.dll.manifest

Como adicionar:

Em Application Folder → botão direito → Add/Adicionar > File/Arquivo…

Selecione a partir de:
C:\Src\TickMark\AuditorAddInRibbon\bin\Release\

✅ Isso foi o que “fechou o ciclo” (registro aponta para [TARGETDIR]AuditorAddInRibbon.vsto e agora o arquivo existe no TARGETDIR).

5) Padronizar o caminho de instalação (per-user) e evitar duplicidade

Você escolheu a estratégia mais prática: instalação por usuário, em LocalAppData.

Ajustar Manufacturer e ProductName (identidade do produto)

No projeto AuditorAddInRibbon_Installer:

Abra Propriedades (F4)

Você definiu:

Manufacturer = TCEES-NGF

ProductName = TickMark_Pt

Isso não renomeia nada no seu código nem no repositório. Só muda “nome do produto” e pasta padrão do instalador.

Ajustar DefaultLocation (onde realmente muda o TARGETDIR)

Não fica nas propriedades do projeto — fica nas propriedades do Application Folder.

Como achar:

File System

Clique em Application Folder

Pressione F4 (Propriedades do Application Folder)

Aí você muda DefaultLocation.

Erro que aconteceu

Você colocou:

[%LocalAppDataFolder%]\...
e o instalador deu erro “Invalid default location”.

Forma correta que funcionou

Você ajustou para:

[LocalAppDataFolder]TCEES-NGF\TickMark_Pt\

✅ Isso passou e fez TARGETDIR virar AppData\Local\TCEES-NGF\TickMark_Pt\.

Evitar duplicidade ao atualizar

No projeto do instalador (F4 nas propriedades do projeto):

RemovePreviousVersions = True

DetectNewerInstalledVersion = True (já estava True)

Regra para novas versões:

aumente Version

quando o VS perguntar se quer atualizar o ProductCode, diga Sim

✅ Isso evita acumular versões/pastas e diminuir risco de “duas entradas” no Excel.

No alvo:

Manifest apontando para algo como:
C:\Users\<usuario>\AppData\Local\TCEES-NGF\TickMark_Pt\AuditorAddInRibbon.vsto|vstolocal

E confira também duplicidade:

HKLM\Software\Microsoft\Office\Excel\Addins
(ideal: não ter a mesma chave lá, já que sua estratégia é por usuário)

Você concluiu corretamente: para distribuição “qualquer pessoa”, sem compra de certificado, o aviso pode aparecer e o usuário decide se confia/instala.
